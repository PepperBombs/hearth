# Notes: every folder and command, in full

What each folder holds and what each command does, in detail. `AGENTS.md` has the short form.

| Folder | Holds |
|---|---|
| `packages/shared` | Types and schemas shared by server and web: the API contract. Change it first, then both sides. It holds the shapes of every route's request and answer (section A8 of the mini-app contract, the assistant's level of section F, and those of `docs/platform.md`: a made app's rows, the catalog, each person's model and the chat's events), and `Json`, a value that survives being sent as JSON. |
| `packages/sdk` | `@hearth/sdk`, the rules every app's manifest keeps to and the UI kit. `@hearth/sdk` (`src/index.ts`) is the manifest's types (`Manifest`, `Setting`, `Localized`) and the lists of allowed names (`APP_ICONS`, `APP_COLORS`, `SPACE_KINDS`, `WIDGET_SIZES`, `SETTING_SCOPES`, `APP_ID_PATTERN`), and imports nothing. `@hearth/sdk/manifest-schema` is the run-time check of a manifest (`manifestSchema`) and of a setting's value (`settingValueProblems`): the server checks every made app's manifest by it (`checkMadeManifest`) and every setting saved, and the web app's settings dialog every value before it sends it. `@hearth/sdk/web` (`src/web`) is the UI kit the shell is built from. Imports no other Hearth package. |
| `packages/server` | Hono server: config, SQLite and migrations (`src/db`), identity, membership, `/api` routes, static files. `src/main.ts` runs `serveHearth` (`src/serve.ts`): the process (settings checked before the database opens, migrations, signals, a rejected promise nothing handled logged instead of ending it) around `startServer`, which makes the apps' way out, brings the built-in apps up to date and moves the old apps' installs to them, then makes the application and the listening socket, and stops them in order. `src/apps` is apps in spaces: `registry.ts` (the types of what every part of the server asks of an app; the registry itself is `madeAppsRegistry` in `src/made/apps.ts`), `installs.ts` (who may use which app where, `VISIBLE`; bring back, remove, move to another space, delete data, each person's switch and pin; the owners' list, `listSpaceApps`, and the access route's work, `setAppAccess`), `store.ts` (the collections an app's rows are read and written through, `AppError`, and the only SQL for `app_rows` and `app_settings`), `settings.ts` (an app's settings in a space: the two routes' work), `fetch.ts` (`hearth.fetch`: the rules, the pace, Node's transport and the stand-in file, `FetchError`; `outboundFor` picks the last two from the settings), `routes.ts` (every route about an app in a space but its page and rows), and `test-world.ts` and `test-clock.ts` (a world of people, spaces and made apps, and a clock that moves only when told, for the server's tests). `src/made` is apps made in Hearth: `manifest.ts` (a made app's manifest and page, their checks, and the schemas of its rows), `apps.ts` (`made_apps` and its versions: making an app, reaching its rows, changing it, going back to a version, `madeAppsRegistry`), `frame.ts` (the page as the sandbox gets it: the app's HTML with the theme's colours and the bridge in front, and its Content-Security-Policy), `catalog.ts` (the built-in apps, read and checked at start-up), `builtin.ts` (their untouched copies brought up to date, and the move of the old apps' installs to them) and `routes.ts` (the catalog, adding from it, the frame, the rows, a fetch, going back to a version). `catalog/<id>` holds a built-in app's `manifest.json` and `page.html`, written by hand. `src/model` is each person's own model and the chat: `settings.ts` (the model and its sealed key), `providers.ts` (the two protocols), `chat.ts` (the tools and their loop), `chats.ts` (each person's kept conversations, `chats` and `chat_entries`, and what the model is given of one) and `routes.ts`. `src/groups` is groups and their people: `policy.ts` (`groupRights`: who may create groups and invite), `members.ts` (create, rename, add or invite, change, remove or leave, take an invitation back) and `routes.ts`. `src/assistant` is the assistant's switches (section F's, which now decide what each person's own model may do in the chat): `level.ts` (`setAssistantLevel`, a space's level, owners only) and `routes.ts`; leaving one app out goes through the access route. `src/http` holds what routes share: `Refusal`, `readBody`, the security middleware. |
| `packages/web` | React app: shell, pages, quick switcher, themes, `src/i18n` (English and Chinese), `src/styles` (the design tokens and the Tailwind theme). Its buttons, inputs, dialogs and so on come from `@hearth/sdk/web`; the card, the avatar and `LinkedText` in `src/components` are the shell's own. `src/made` is apps made in Hearth in the browser: `frame.tsx` (`<MadeAppFrame>`, an app's page in its sandboxed iframe, and the other end of its bridge, which answers for that app in that space alone), `api.ts` (what the bridge asks the server for, the catalog, each person's model, the chat's stream and going back to a version) and `model-card.tsx` (the Settings card for a person's own model). `src/pages/chat.tsx` is the chat. `src/apps` is what the shell does with an app as a whole: `api.ts` (its settings, removing it, moving it, the person's switch and pin), `manage.tsx` (adding a built-in app, removing, moving, switch and pin, and the settings button), `settings.ts` (the settings an app declares, and the dialog's query of their values) and `settings-dialog.tsx` (the settings form drawn from them). `src/pages/dashboard.tsx` draws a card for each app with its page inside, small, and `src/pages/app-page.tsx` an app's own page; `src/pages/apps.tsx` is the Apps page, with the dialogs that add a built-in app, move an app and remove it; the one that adds names the hosts a built-in app fetches from. `src/groups` is the groups' cards in Settings: `groups.tsx` (the cards, creating, renaming, leaving), `people.tsx` (the people, adding, the dialog for one person, invitations), `access-table.tsx` (the member-by-app table), `api.ts` and `queries.ts`. `src/assistant/assistant-card.tsx` is the Assistant card in Settings: for each of the person's spaces, what their own model may do there (a three-way control for its owners, words for members) and, for owners, the apps it may use. |
| `e2e` | Playwright end-to-end tests (`playwright.config.ts` at the root). `servers.ts` holds the addresses, the people, the command that starts a copy of the built server (`realServerCommand`), and the file of stand-in answers for every fetch an app makes there (`STAND_INS`), which tests write with `writeStandIns`. |
| `deploy` | Pull-based deploy script, systemd units, polkit rule, example config. Each release is the framework alone, `main` of this repository, built. The copy of the script installed on a server is a starter: it hands each run over to the deploy script of the newest framework commit (`SELF_UPDATE`, on unless `deploy.conf` says off), so it is installed once. The systemd units and the polkit rule are still installed by hand, from the running release (`current/hearth/deploy`): the deploy only fetches into the checkout it builds from, whose files stay as cloned. Run on one real server: the whole guide with the releases up to the grocery list, and since then the hand-over on its ordinary path (the one-time install, and one release handed to its own script and deployed by it); what it does when something is wrong (a broken script, a failed fetch, `SELF_UPDATE=off`) has run only in its tests. `deploy/tests` runs the script against stand-ins for git, pnpm and systemctl, and once against the real git. |
| `.github/workflows` | `ci.yml`: types, lint, unit tests and the build (`check`), and the built app end to end (`e2e`). |
| `docs` | `architecture.md`, `platform.md` (apps made in Hearth, the chat and each person's model), `self-hosting.md`, and `mini-app-contract.md`: the record of the framework of mini-apps, removed in November 2026, and of the assistant's switches (section F), which stay. |

Commands, from the repository root (Node 22, pnpm 10):

| Command | Does |
|---|---|
| `pnpm install` | Install dependencies. |
| `HEARTH_AUTH=dev HEARTH_OWNER_EMAIL=you@example.com pnpm dev` | Run server (port 4310) and web dev server (port 5173) with sign-in switched off. Both ports are fixed, so a dev server still running, even one left from another session, keeps it from starting. A built-in GitHub Trending fetches from the real `api.github.com` when someone who may edit it opens it; add `HEARTH_FETCH_STANDINS=<absolute path>` to answer every app's fetches from a file instead (`packages/server/README.md`), and `HEARTH_MODEL_STANDIN=<address>` to send every chat to a stand-in model. |
| `pnpm check` | Type checking (the packages and `e2e`), lint, unit tests and the deploy script's tests. Run before every push. |
| `pnpm build` | Build shared, web and server. |
| `pnpm e2e` | End-to-end tests against the built app. They build the web app and the server themselves first. |
| `pnpm start` | Start the built server. |
